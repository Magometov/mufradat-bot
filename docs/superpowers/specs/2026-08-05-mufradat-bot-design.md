# Mufradat Bot — дизайн

Дата: 2026-08-05

**Ревизия 3.** Против ревизии 1: бэкенд переведён с FastAPI + SQLAlchemy на
Django + DRF; к карточкам добавлены картинки с автоподбором из Openverse; фразы и
словоформы стали полноценными единицами заучивания; поведение ИИ вынесено в
редактируемый файл `content/curriculum.yaml`.

## 1. Что строим

Закрытое приложение внутри Telegram для группы ~10 человек, которые вместе учат
литературный арабский по учебнику «العربية بين يديك». Колода общая на всех: админ
наполняет базу, остальные учат по карточкам. Прогресс у каждого свой.

Три входа:

| Вход | Кому | Зачем |
|---|---|---|
| Telegram Mini App | всем | учёба по карточкам |
| Чат с ботом | админу | наполнение базы |
| Админка Django | staff | правка базы без кода |

## 2. Роли

| Роль | Права |
|---|---|
| Админ (Telegram ID из `ADMIN_TELEGRAM_IDS`) | Наполнение: импорт по фото, ручной ввод, подбор картинок, генерация. Плюс всё, что может пользователь. |
| Пользователь | Только учёба через Mini App и свой прогресс. Никаких вызовов ИИ. |
| Staff в админке Django | Правка базы через веб-админку, вход по логину и паролю Django. |

Гейтинг телеграм-админа — по Telegram ID из конфигурации, проверка в одном месте
(фильтр aiogram). Это отдельный от Django-аккаунтов механизм: у ученика нет
пароля, у staff нет Telegram ID, смешивать их в кастомной модели пользователя
незачем.

### Бот и Django ORM

Процесс бота вызывает `django.setup()` и работает с ORM напрямую. Два места, где
это требует внимания:

- Чтение и одиночные записи — через асинхронные методы ORM (`aget`, `acreate`,
  `async for`).
- **`transaction.atomic()` асинхронного варианта не имеет.** Сохранение
  подтверждённого набора — одна транзакция на много строк, поэтому эта функция
  пишется синхронной и вызывается через `asgiref.sync.sync_to_async`.

## 4. Модель данных

Сущность «Урок» не создаётся. Её три функции закрыты иначе: ограничение
ИИ-генерации пройденной лексикой (колода общая и все на одном уровне, значит вся
таблица `Entry` и есть пройденная лексика), порядок ввода нового (`created_at` +
суточный лимит), фильтр в «Тренировке» (`topic` + `created_at`).

### Схема строится по частям

Полная схема ниже — целевая. Таблицы заводятся тем этапом, который ими реально
пользуется, чтобы не замораживать в миграции то, что ещё не проверено кодом:

| Что | Появляется на этапе |
|---|---|
| `Entry` без форм и картинок (слово, фраза) | 2 — домен |
| `Sentence`, `SentenceEntry` | 5 — импорт по фото, там появляются диалоги |
| Картинки: `translation_en`, `image`, `image_attribution`, `image_source_url` | 6 |
| `TelegramUser`, `UserProgress`, `ReviewLog` | 7 — вместе с FSRS |
| Формы: `kind=form`, `base`, `person`, `tense`, `pos` и их ограничения | 9 |

### Entry — единица заучивания

Одна таблица на всё, что попадает в карточки. Слово, фраза и словоформа
структурно не различаются: арабское с огласовками, перевод, транслитерация,
картинка, примеры. Различаются только типом.

| kind | Пример | Что это |
|---|---|---|
| `word` | `بَيْت` — дом | слово из учебника |
| `phrase` | `مَا اسْمُكَ؟` — как тебя зовут? (к мужчине) | функциональная фраза |
| `form` | `سَيَّارَتُهُ` — его машина | словоформа с местоимением |

Поля:

| Поле | Тип | Примечание |
|---|---|---|
| `id` | PK | |
| `kind` | choices | `word` \| `phrase` \| `form` |
| `arabic` | text | с огласовками, как распознано |
| `arabic_norm` | text | скелет без огласовок, для дедупликации |
| `translation_ru` | text | у формы — «его машина», у фразы — с пометкой «(к мужчине)» |
| `translation_en` | text, null | служебный, только как поисковый запрос к Openverse |
| `transliteration` | text, null | обязателен у форм — см. §8 |
| `pos` | choices, null | `noun` \| `verb`; нужен, чтобы знать, какие формы уместны |
| `base` | FK на Entry, null | заполнен у `form`: у `سَيَّارَتُهُ` это `سَيَّارَة` |
| `person` | choices, null | `ana`, `huwa`, `hiya`, `anta`, `anti`, `nahnu`. У `form` — лицо формы; у `phrase` — к кому обращение (`anta` / `anti`) |
| `tense` | choices, null | у глагольных форм: `past` \| `present`; у притяжательных пусто |
| `topic` | text, null | свободная метка, замена уроку |
| `source` | choices | `textbook` \| `manual` \| `ai_generated` |
| `image` | ImageField, null | у формы пусто — наследуется от `base` |
| `image_attribution` | text, null | обязательна для CC BY / BY-SA |
| `image_source_url` | text, null | |
| `created_at` | timestamptz | |

Ограничения:

- `unique_together = ("arabic", "translation_ru")` — по **точному** арабскому, а не
  по нормализованному. Причина в §4.1: пары «к мужчине / к женщине» различаются
  только харакой, и уникальность по скелету запрещала бы половину нужного контента.
- `arabic_norm` — индексируется, но в ограничениях не участвует: он служит только
  для поиска похожих при импорте (§4.2).
- У формы `base` и `person` обязательны, `unique_together = ("base", "person",
  "tense")`. `person` и `tense` хранят пустую строку, а не NULL, — иначе две
  притяжательные формы с пустым `tense` прошли бы обе, так как в Postgres NULL-ы
  считаются различными.
- Картинка формы наследуется от базы на уровне представления (`image or
  base.image`), в БД не копируется.
- `arabic_norm` заполняется в `save()` модели, а не вызывающим кодом, чтобы
  инвариант нельзя было забыть. `bulk_create` обходит `save()` — там норму нужно
  проставлять явно.

### Остальные модели

| Модель | Поля |
|---|---|
| `TelegramUser` | `telegram_id` (PK, BigInteger), `username`, `first_name`, `new_per_day` (int, 5), `created_at` |
| `Sentence` | `id`, `arabic`, `translation_ru`, `source`, `created_at` — только примеры употребления, карточками не становятся |
| `SentenceEntry` | `sentence` (FK), `entry` (FK), `unique_together` |
| `UserProgress` | `id`, `telegram_user` (FK), `entry` (FK), `direction`, `due`, `fsrs_state` (JSONField), `updated_at`; `unique_together = (telegram_user, entry, direction)`, индекс `(telegram_user, due)` |
| `ReviewLog` | `id`, `telegram_id` (BigInteger, **без FK** — история переживает удаление пользователя), `entry` (FK), `direction`, `rating` (1..4), `reviewed_at` |

`UserProgress` ссылается на `Entry` одним FK — поэтому очереди, три режима и два
направления не усложняются от того, что единицы бывают трёх типов.

Модель учеников называется `TelegramUser`, а не `User`: имя `User` и таблица
`auth_user` заняты Django.

Все временные метки — `TIMESTAMPTZ` (`USE_TZ = True`). `kind`, `pos`, `person`,
`tense`, `direction`, `source` — `TextChoices`, в БД хранятся значения.

### Нормализация арабского (`vocabulary/services/arabic.py`)

`arabic_norm` строится из `arabic`:

1. удаляются знаки огласовки `U+064B..U+065F`, `U+0670`, коранические
   `U+06D6..U+06ED`;
2. удаляется татвиль `U+0640`;
3. формы алифа `أ إ آ ٱ` → `ا`;
4. алиф максура `ى` → `ي`.

`ة` и `ه` **не** объединяются — это меняет смысл слова.

Зачем: vision-модель может вернуть то же слово с чуть иной расстановкой харакат, и
сравнение по точной строке такой дубль пропустит.

### 4.1. Конфликт: нормализация слепа к роду

Снятие харакат ловит разброс распознавания — и ровно поэтому теряет различие,
которое группа сейчас учит:

| Пара | Нормализованная форма |
|---|---|
| `مَا اسْمُكَ؟` (к мужчине) / `مَا اسْمُكِ؟` (к женщине) | обе → `ما اسمك؟` |
| `أَنْتَ` / `أَنْتِ` | обе → `انت` |
| `كَتَبْتَ` (ты написал) / `كَتَبْتِ` (ты написала) | обе → `كتبت` |

Различие живёт в одном значке, который нормализация выбрасывает. Отсюда два
следствия, заложенные в модель:

- уникальность — по **точному** `arabic`, иначе база запретила бы женскую форму
  после мужской;
- у фраз и форм есть структурное поле `person`, поэтому род обращения не зависит
  от того, не забыл ли админ дописать «(к женщине)» в перевод.

### 4.2. Дедупликация

`arabic_norm` используется как корзина кандидатов, внутри которой сравнивается
точный `arabic`:

| Исход | Условие | Что делает бот |
|---|---|---|
| `NONE` | ничего похожего | добавляет без вопросов |
| `EXACT` | тот же `arabic` и тот же перевод | помечает как уже существующее, не предлагает |
| `SIMILAR` | совпал скелет, но не точный `arabic` или не перевод | показывает найденную запись рядом, решает админ |

У `SIMILAR` есть флаг «перевод совпадает». Он совпадает — почти наверняка то же
слово с другими огласовками, стоит пропустить. Не совпадает — либо омограф, либо
парная форма другого рода, и её как раз нужно добавить.

### Сопоставление слов предложения со словарём

Связка `SentenceEntry` строится автоматически. Наивное сравнение не работает: в
тексте слово идёт с артиклем `ال` и слитными предлогами и союзами (`و`, `ف`, `ب`,
`ل`, `ك`), поэтому `الْكِتَابُ` не совпадёт с `كِتَاب`. Для каждого токена
перебираются варианты — полная форма, без артикля, без слитной частицы, без
частицы и артикля — и берётся первое попадание в словарь. Полная форма проверяется
первой, чтобы `بَيْت` не разобралось как `ب` + `يت`.

## 5. Наполнение базы

Три источника, все проходят через подтверждение админом кнопками
✅ добавить / ✏️ править / ❌ пропустить.

### 5.1. Фото страницы учебника

1. `/import` → бот просит фото (можно несколько, в том числе альбомом).
2. Максимальный доступный размер → base64 → Claude vision со structured output:
   `words[{arabic, translation_ru, translation_en, transliteration?, pos?}]`,
   `sentences[{arabic, translation_ru}]`.
3. Дедупликация по `arabic_norm`: существующие помечаются и не предлагаются.
4. Подтверждение по каждому элементу; ✏️ переводит FSM в ожидание строки
   `арабское | перевод`.
5. «Сохранить подтверждённое» → одна транзакция (синхронная функция через
   `sync_to_async`): записи `Entry`, `Sentence`, `SentenceEntry`.
6. `/topic <метка>` задаёт `topic` для текущей партии.

Настройки вызова модели: structured outputs, adaptive thinking (включён по
умолчанию на Sonnet 5), `effort: medium` как старт. `temperature` не передаётся —
на Sonnet 5 недефолтные sampling-параметры отклоняются с 400.

### 5.2. Ручной ввод

`/add` — ввод фразы или слова руками, строкой `арабское | перевод`. Это первый
источник фраз: то, что реально звучало на занятии. Эти же фразы становятся
примерами в `content/curriculum.yaml` для последующей генерации.

### 5.3. Словоформы

Формы заводятся не таблицей, а по выбору: `/forms <слово>` просит у модели
несколько форм для указанных в конфиге лиц, админ подтверждает нужные. Каждая
подтверждённая форма становится отдельной единицей `Entry` с `kind=form`.

Почему отдельными карточками, а не таблицей на обороте: цель заучивания — сама
форма («его машина»), а не абстрактная лемма. Только при отдельных карточках FSRS
может знать, что формы с `أنا` пользователь помнит, а с `أنتِ` путает.

Почему не случайная подстановка местоимения при показе: интервальное повторение
держится на том, что повторяется одно и то же. Если единица меняется от показа к
показу, оценки сложности теряют смысл, повторить конкретно провальную форму нельзя,
а покрытие лиц становится случайным. Разнообразие «иногда выходят разные формы»
получается само — у разных карточек разные сроки.

Рост колоды сдерживается двумя ручками: `forms_per_entry` в конфиге и суточный
лимит новых карточек `new_per_day` (формы идут в ту же очередь новых, что и слова).

### 5.4. ИИ-генерация

Пакетная, по темам из `content/curriculum.yaml`, результат кэшируется в БД.
Правила: только лексика из базы плюс служебный набор (предлоги, местоимения,
частицы); лица — только перечисленные в конфиге; **не более одного нового слова**
на предложение, и это новое слово возвращается отдельным пунктом как кандидат — в
базу попадает только после подтверждения. Иначе §8 нарушается втихую: слово,
придуманное моделью, — ровно тот случай, где незаметно ломаются огласовки.

## 6. Файл поведения ИИ (`content/curriculum.yaml`)

Редактируется без правки кода. Формат — YAML (нужны комментарии), читается через
Pydantic, поэтому опечатка даёт внятную ошибку, а не странный промпт.

Главный рычаг — **примеры**, а не инструкции прозой: модель на порядок точнее
ловит стиль по двум-трём образцам, чем по описанию. Дописал пример в тему —
изменилась вся её выдача.

```yaml
rules:
  register: msa                      # литературный, по «العربية بين يديك»
  harakat: required
  max_new_words_per_sentence: 1
  forms_per_entry: 2                 # сколько форм просить на слово
  pronouns: [ana, huwa, hiya, anta, anti, nahnu]
  service_words: [فِي, مِنْ, إِلَى, هَذَا, هَذِهِ]

topics:
  - id: introductions
    title: Знакомство
    enabled: true
    target_count: 12
    ask_for:
      - вопрос и ответ об имени
      - вопрос и ответ о происхождении
    examples:
      - ar: مَا اسْمُكَ؟
        ru: как тебя зовут? (к мужчине)
      - ar: مِنْ أَيْنَ أَنْتَ؟
        ru: откуда ты? (к мужчине)
```

`pronouns` — центральная настройка: один список управляет и тем, какие лица
генерировать в формах, и тем, какие использовать во фразах. Прошли новое
местоимение — дописал строку. Отдельной настройки «формы обращения» нет: `anta` и
`anti` в этом списке и есть «(к мужчине)» и «(к женщине)».

Темы включаются и выключаются флагом `enabled`, не удаляясь.

## 7. Учёба в Mini App

Карточка: единица на лицевой стороне, тап → переворот. Каждая единица даёт две
независимые карточки: `ar_ru` и `ru_ar`.

Что на какой стороне — вопрос корректности, а не оформления:

| Направление | Лицо | Оборот |
|---|---|---|
| `ar_ru` | арабское с огласовками | перевод, транслитерация, **картинка**, примеры |
| `ru_ar` | перевод + **картинка** | арабское с огласовками, транслитерация, примеры |

Картинка на лице `ar_ru` выдала бы ответ — вместо припоминания перевода получилось
бы узнавание картинки. На `ru_ar` она арабского не выдаёт, а припоминание идёт от
образа, а не от русского слова, что сильнее. Полный список форм на обороте **не
показывается** — форма является отдельной карточкой.

Три режима:

| Режим | Что даёт | Пишет в FSRS |
|---|---|---|
| «На сегодня» | что пора по расписанию, старое и новое вперемешку | да |
| «Новые» | единицы без прогресса, с учётом `new_per_day`; на кнопке счётчик | да (создаёт карточку) |
| «Тренировка» | всё выученное вне расписания, фильтр по `topic` и «последние N» | **нет** |

Отдельного режима «только старые» нет — его закрывает фильтр в «Тренировке».

«Новизна» слова в примере **не хранится**: слово считается новым, если для него нет
строки в `UserProgress`. Считается на сервере, у каждого своё. Такое слово
подсвечивается в примере, рядом кнопка «Добавить в изучение».

- Источник: автоподбор из Openverse плюс своё фото в бота; выбор кнопкой.
- Openverse проверен живым запросом 2026-08-05:
  `GET https://api.openverse.org/v1/images/?q=<en>&page_size=3&license=cc0,pdm,by,by-sa`;
  ключ не нужен, анонимные лимиты в заголовках ответа **20/мин и 200/день**, фильтр
  лицензий работает, в ответе есть готовая строка `attribution`.
- **Запрос идёт по-английски.** Проверено: по `хлеб` первым результатом приходит
  картинка с русским текстом о здоровье, по `bread` — чистые фотографии. Поэтому
  vision-модель просят вернуть заодно `translation_en`; в интерфейсе он не
  показывается.
- Хранится своим файлом, не ссылкой: телеграмная ссылка содержит токен бота и живёт
  около часа, а хотлинк на Openverse зависит от внешнего источника.
- Атрибуция сохраняется обязательно — этого требуют CC BY и BY-SA.
- Картинки нужны конкретным существительным и бесполезны для абстракций и частиц,
  поэтому неполное покрытие — правильное поведение, а не компромисс.

## 8. Правила по огласовкам

- Всё арабское хранится с огласовками.
- Приоритет — считать огласовки как есть с фото, а не расставлять заново.
- Vision-модель может терять часть харакат, поэтому подтверждение админом
  обязательно везде.
- **У словоформ и парных фраз транслитерация обязательна.** `كَتَبْتَ` (ты написал) и `كَتَبْتِ`
  (ты написала) различаются только последней харакой — ровно то различие, которое
  группа сейчас учит. Глазами разницу в одной точке легко пропустить, а `katabta` /
  `katabti` не спутаешь, поэтому в подтверждении транслитерация показывается рядом.
- Библиотека простановки огласовок — только запасной вариант для источников без
  огласовок, по умолчанию не используется.
- Неправильная харака = неправильно выученное произношение; качество здесь важнее
  скорости.

## 9. API для Mini App (DRF)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/stats/` | счётчики для главной |
| GET | `/api/v1/queue/due/` | карточки по расписанию |
| GET | `/api/v1/queue/new/` | единицы без прогресса, с учётом суточного лимита |
| GET | `/api/v1/queue/training/?topic=&recent=` | всё выученное вне расписания, только чтение |
| POST | `/api/v1/review/` | `{entry_id, direction, rating}` → обновление FSRS, возвращает новый `due` |
| POST | `/api/v1/entries/<id>/learn/` | завести карточки для единицы |

Реализация — классы `APIView` с сериализаторами DRF. `ModelViewSet` не
используется: это не CRUD над моделью, а вычисляемые очереди.

### Авторизация

Mini App присылает подписанные `initData`. Проверка — в собственном классе
DRF-аутентификации: `HMAC_SHA256(key=HMAC_SHA256("WebAppData", bot_token),
msg=data_check_string)` плюс свежесть `auth_date`; при успехе возвращается
`TelegramUser`. Ни один эндпоинт не принимает `telegram_id` от клиента — только из
проверенной подписи. Отсутствующий пользователь создаётся при первом валидном
запросе.

## 10. Конфигурация (`.env`)

Параметры БД задаются по частям: их читают и `docker-compose.yml`, и Django, нигде
не дублируясь. `.env.example` содержит только имена и комментарии; значения живут в
`.env`, который в `.gitignore`. Пустое значение трактуется как «использовать
значение по умолчанию», чтобы `.env`, скопированный из шаблона, ничего не ломал.

```
POSTGRES_USER=  POSTGRES_PASSWORD=  POSTGRES_NAME=  POSTGRES_HOST=  POSTGRES_PORT=
DJANGO_SECRET_KEY=  DJANGO_DEBUG=
BOT_TOKEN=  ADMIN_TELEGRAM_IDS=  WEBAPP_URL=
ANTHROPIC_API_KEY=  AI_MODEL=
```

## 11. Принятые решения и обоснования

### Django вместо FastAPI

Владелец поддерживает Django сам. Менять пришлось не «слой API», а весь слой
данных, иначе в проекте оказались бы две ORM: ушли SQLAlchemy, Alembic и asyncpg,
пришли Django ORM, миграции Django и psycopg 3.

Побочный выигрыш: **админка Django закрывает требование «править базу» без единой
строки кода** — из объёма уходит отдельный редактор через бота. Плюс
`pytest-django` сам создаёт и удаляет тестовую базу, поэтому отдельная база и
init-скрипт для неё не нужны.

Цена: процесс бота асинхронный, а `transaction.atomic()` синхронный (см. §3).

### Одна таблица `Entry` вместо трёх

Слово, фраза и словоформа структурно совпадают. Альтернатива — отдельные таблицы и
`UserProgress` с несколькими nullable FK и constraint «заполнен ровно один»;
сложность переехала бы в слой очередей, самый нагруженный код проекта (три режима ×
два направления × вычисление новизны).

### Модель ИИ: `claude-sonnet-5`

Стоимость страницы учебника (~6 000 входных токенов с картинкой в высоком
разрешении + ~2 000 выходных с огласовками):

| Модель | $/1M вход/выход | Разрешение | ~страница | Учебник ~150 стр. |
|---|---|---|---|---|
| Haiku 4.5 | 1 / 5 | 1568px | ~$0.013 | ~$2 |
| Sonnet 5 | 3 / 15 (акция 2 / 10 до 31.08.2026) | 2576px | ~$0.03 | ~$5 |
| Opus 5 | 5 / 25 | 2576px | ~$0.08 | ~$12 |

Разница между самым дешёвым и выбранным — около четырёх долларов за всё время
жизни проекта, поэтому решающий фактор не цена, а разрешение: харака — штрих в
несколько пикселей, Haiku сжимает картинку до 1568px, Sonnet 5 держит 2576px.
Модель вынесена в `AI_MODEL`.

### FSRS считается на сервере

- «Тренировка» обязана не менять состояние. На сервере это отсутствие вызова —
  сломать нечего. На клиенте пришлось бы принимать посчитанное состояние, и любой
  баг во фронтенде ломал бы интервалы всей колоды.
- Одна реализация вместо двух: библиотека Python, иначе нужен порт на JS.
- Прогресс переживает переустановку Telegram, открывается с любого устройства.
- История в `ReviewLog` для будущей подгонки параметров всё равно нужна на сервере.

Плата — HTTP-запрос на карточку (~20–30 за сессию). Лечится оптимистичным UI:
следующая карточка показывается сразу, запрос уходит в фоне.

### `arabic-diacritizer` — опциональная зависимость

Единственный живой вариант (BiLSTM+attention, 6.6% DER, март 2026): `mishkal` —
2021 год, `shakkala` тянет TensorFlow, `libtashkeel` на PyPI не публикуется. Но
колесо весит 47 МБ и требует `torch>=2.1` (ещё ~1–2 ГБ) ради ветки, которая по §8 в
норме не вызывается. Реализация написана и работает, но ставится отдельной группой
зависимостей.

### Frontend: Vue 3 + Vite

Соответствует конвенциям, по которым владелец пишет сам (Vue 3 SFC, CSS Modules,
rem). SPA без Nuxt: внутри Telegram SSR не нужен, отдаём статику.

## 12. Этапы

Каждый этап заканчивается проверкой и ожидает одобрения владельца.

| # | Этап | Проверка |
|---|---|---|
| 1 | Каркас: Django-проект, конфиг, Postgres 16 в Docker | `manage.py check` и `migrate` проходят, тесты конфига зелёные |
| 2 | Домен: нормализация, сопоставление слов, модели, миграции, админка, дедупликация, `curriculum.yaml` с загрузчиком, сидер | тесты зелёные, сидер заливает колоду, админка открывается |
| 3 | Скелет бота: `/start` печатает Telegram ID, роли, `/help` | бот отвечает, ID вписан в `.env` |
| 4 | Ручной ввод `/add`: слова и фразы с занятий | фраза с занятия попала в базу и стала карточкой |
| 5 | Импорт по фото: vision, дедупликация, подтверждение | реальное фото страницы → слова и предложения в БД |
| 6 | Картинки: автоподбор Openverse, своё фото, атрибуция | у слова картинка с корректной атрибуцией, у формы — наследованная |
| 7 | DRF: аутентификация по `initData`, очереди, FSRS | тесты подписи, очереди отвечают, `POST /review/` двигает `due` |
| 8 | Mini App: три режима, переворот, картинки, примеры | открывается в Telegram через cloudflared, карточки работают |
| 9 | Словоформы `/forms` и генерация по темам | формы и фразы генерируются по конфигу, подтверждаются кнопками |
| 10 | Полировка: счётчики, фильтры, лимиты, обработка ошибок | сценарий «новичок с нуля» проходит от `/start` до повторения |

Ручной ввод (этап 4) идёт раньше импорта по фото и генерации: он даёт работающие
карточки быстрее всего и наполняет `curriculum.yaml` живыми примерами с занятий,
на которые потом опирается генерация.

Тесты вперёд там, где чистая логика: нормализация, сопоставление слов,
дедупликация, загрузчик конфига, валидация `initData`, переходы FSRS. UI
проверяется вручную в Telegram.

Локальный Postgres 14 не трогается — база в Docker (16) на порту 5433.

## 13. Вне объёма

- Продакшн-деплой: позже (сейчас локальный запуск — polling + туннель cloudflared
  для HTTPS Mini App).
- Озвучка слов; корень и порода глагола — исключены владельцем.
- Статистика по группе, напоминания «пора повторять» — не запрашивались.
- Сущность «Урок», режим «только старые слова», несколько колод, больше одной
  картинки на единицу.
- Режим-тренажёр спряжений («поставь глагол в форму для „она"») — владелец просил
  видеть формы, а не отрабатывать их отдельным упражнением.
- Подгонка параметров FSRS под группу: данные копятся в `ReviewLog`, сама подгонка
  не делается.
