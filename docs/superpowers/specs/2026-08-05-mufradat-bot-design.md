# Mufradat Bot — дизайн

Дата: 2026-08-05

## 1. Что строим

Закрытое приложение внутри Telegram для группы ~10 человек, которые вместе учат
арабский на одном уровне. Общая колода слов на всех: админ наполняет базу через
фото страниц учебника, остальные учат по карточкам. Личный прогресс — у каждого
свой.

Два формата в одном боте:

- **Telegram Mini App** — интерфейс учёбы (карточки) для всех.
- **Чат с ботом** — инструмент импорта для админа: фото страницы → ИИ достаёт
  слова и диалоги → админ подтверждает → запись в базу.

## 2. Роли

| Роль | Права |
|---|---|
| Админ (Telegram ID из `ADMIN_TELEGRAM_IDS`) | Импорт по фото, генерация предложений, правка базы. Плюс всё, что может пользователь. |
| Пользователь | Только учёба через Mini App и свой прогресс. Никаких вызовов ИИ. |

Гейтинг админа — по Telegram ID из конфигурации, проверка в одном месте
(зависимость FastAPI / фильтр aiogram), а не россыпью по хендлерам.

## 3. Стек

Версии проверены на PyPI 2026-08-05, Python 3.12.

| Компонент | Выбор |
|---|---|
| Бот | `aiogram` 3.30 (polling в разработке) |
| API | `fastapi` 0.141 + `uvicorn` |
| БД | PostgreSQL 16 в Docker + `SQLAlchemy` 2.0 (async) + `alembic` 1.19 |
| Интервальное повторение | `fsrs` 6.3.1 (зависимость только `typing-extensions`) |
| ИИ | Anthropic Claude, модель `claude-sonnet-5` (в `.env`), structured outputs через `messages.parse()` |
| Огласовки (fallback) | `arabic-diacritizer` 1.0.0 — **опциональная** группа зависимостей |
| Frontend | Vue 3 + Vite (SPA, без Nuxt), CSS Modules, rem-сетка |
| Конфигурация | `pydantic-settings` из `.env` |

Два процесса на общей БД и общих моделях: `bot` (aiogram) и `api` (FastAPI, он
же раздаёт собранный Mini App как статику).

## 4. Модель данных

Сущность «Урок» не создаётся. Её три функции закрыты иначе:

- ограничение ИИ-генерации «только пройденная лексика» — колода общая и все на
  одном уровне, значит вся таблица `words` и есть пройденная лексика;
- порядок ввода новых слов — `created_at` + суточный лимит новых карточек;
- фильтр в «Тренировке» — `topic` и `created_at`.

```sql
CREATE TABLE users (
    telegram_id   BIGINT PRIMARY KEY,
    username      TEXT,
    first_name    TEXT,
    new_per_day   INTEGER NOT NULL DEFAULT 5,   -- лимит новых карточек в день
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE words (
    id              SERIAL PRIMARY KEY,
    arabic          TEXT NOT NULL,              -- как есть, С огласовками
    arabic_norm     TEXT NOT NULL,              -- нормализованная форма, для дедупликации
    translation_ru  TEXT NOT NULL,
    transliteration TEXT,
    topic           TEXT,                       -- свободная метка: «еда», «глаголы движения»
    source          TEXT NOT NULL,              -- 'textbook' | 'ai_generated'
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (arabic_norm, translation_ru)
);
CREATE INDEX ix_words_arabic_norm ON words (arabic_norm);
CREATE INDEX ix_words_created_at  ON words (created_at);

CREATE TABLE sentences (
    id              SERIAL PRIMARY KEY,
    arabic          TEXT NOT NULL,              -- С огласовками
    translation_ru  TEXT NOT NULL,
    source          TEXT NOT NULL,              -- 'textbook' | 'ai_generated'
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Связка предложения со словами словаря.
CREATE TABLE sentence_words (
    sentence_id  INTEGER NOT NULL REFERENCES sentences(id) ON DELETE CASCADE,
    word_id      INTEGER NOT NULL REFERENCES words(id)     ON DELETE CASCADE,
    PRIMARY KEY (sentence_id, word_id)
);

-- Прогресс: одна строка на (пользователь, слово, направление).
CREATE TABLE user_progress (
    id            SERIAL PRIMARY KEY,
    telegram_id   BIGINT  NOT NULL REFERENCES users(telegram_id) ON DELETE CASCADE,
    word_id       INTEGER NOT NULL REFERENCES words(id)          ON DELETE CASCADE,
    direction     TEXT    NOT NULL,             -- 'ar_ru' | 'ru_ar'
    due           TIMESTAMPTZ NOT NULL,
    fsrs_state    JSONB   NOT NULL,             -- сериализованная карточка FSRS
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (telegram_id, word_id, direction)
);
CREATE INDEX ix_user_progress_due ON user_progress (telegram_id, due);

-- История оценок. Нужна, чтобы позже дообучить параметры FSRS под группу;
-- без неё эта возможность закрыта навсегда. FK на users сознательно нет:
-- история должна переживать удаление пользователя.
CREATE TABLE review_log (
    id           SERIAL PRIMARY KEY,
    telegram_id  BIGINT  NOT NULL,
    word_id      INTEGER NOT NULL REFERENCES words(id) ON DELETE CASCADE,
    direction    TEXT    NOT NULL,
    rating       SMALLINT NOT NULL,             -- шкала FSRS: 1..4
    reviewed_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### Нормализация арабского (`services/arabic.py`)

`arabic_norm` строится из `arabic`:

1. удаляются знаки огласовки `U+064B..U+065F`, `U+0670`, коранические
   `U+06D6..U+06ED`;
2. удаляется татвиль `U+0640`;
3. формы алифа `أ إ آ ٱ` → `ا`;
4. алиф максура `ى` → `ي`.

`ة` и `ه` **не** объединяются — это меняет смысл слова.

Зачем: vision-модель может вернуть то же слово с чуть иной расстановкой харакат,
и сравнение по точной строке такой дубль пропустит. Дедупликация идёт по скелету
слова, а огласовки хранятся как распознаны.

Если `arabic_norm` совпал, а `translation_ru` — нет, это не блокировка: боту
показывается предупреждение «в базе есть похожее слово с другим переводом» и
решает админ (омографы существуют).

## 5. Функциональность

### 5.1. Импорт через бота (только админ)

1. `/import` → бот просит фото страницы (можно несколько, в том числе альбомом).
2. Фото → берётся максимальный доступный размер → base64 → Claude vision со
   structured output. Схема ответа (Pydantic): `words[{arabic, translation_ru,
   transliteration?}]`, `sentences[{arabic, translation_ru, word_forms[]}]`.
3. Дедупликация по `arabic_norm`: уже существующие помечаются и не предлагаются.
4. Каждый новый элемент — сообщение с inline-кнопками ✅ добавить / ✏️ править /
   ❌ пропустить. ✏️ переводит FSM в ожидание строки `арабское | перевод`.
5. «Сохранить подтверждённое» → одна транзакция: `words`, `sentences`,
   `sentence_words` (слова предложения сопоставляются со словарём по
   нормализованной форме).
6. `/topic <метка>` задаёт `topic` для текущей партии импорта.

Настройки вызова модели: structured outputs, adaptive thinking (включён по
умолчанию на Sonnet 5), `effort: medium` как старт. `temperature` не
передаётся — на Sonnet 5 недефолтные sampling-параметры отклоняются с 400.

### 5.2. Учёба в Mini App (все)

Карточка: слово на лицевой стороне, тап → переворот → перевод + примеры
употребления из `sentence_words`. Каждое слово даёт две независимые карточки:
`ar_ru` и `ru_ar`.

Три режима на главном экране:

| Режим | Что показывает | Пишет ли в FSRS |
|---|---|---|
| «На сегодня» | карточки, которым по расписанию FSRS пора | да |
| «Новые слова» | слова без строки прогресса, с учётом `users.new_per_day`; на кнопке счётчик | да (создаёт карточку) |
| «Тренировка» | все выученные вне расписания, фильтр по `topic` и «последние N добавленных» | **нет** |

Отдельного режима «только старые слова» нет — его закрывает фильтр в
«Тренировке».

### 5.3. Предложения и новые слова в них

Диалоги из учебника (`source='textbook'`) — основной источник примеров,
сохраняются как есть.

ИИ-генерация (`source='ai_generated'`) — пакетная, при наполнении, результат
кэшируется в БД. Правило: использовать слова из `words` плюс минимальный
служебный набор (предлоги, местоимения, частицы). Модели разрешается ввести
**не более одного нового слова** на предложение, и она обязана вернуть его
отдельным пунктом как кандидата — в `words` оно попадает только после
подтверждения админом кнопкой. Иначе §6 нарушается втихую: новое слово,
придуманное моделью, — ровно тот случай, где незаметно ломаются огласовки.

«Новизна» слова **не хранится**: слово считается новым для пользователя, если
для него нет строки в `user_progress`. Вычисляется на сервере, у каждого своё. В
Mini App такое слово подсвечивается в арабском тексте и в переводе, рядом кнопка
«Добавить в изучение» → `POST /words/{id}/learn`.

Темп «1–2 новых слова в неделю» — это решение админа (сколько кандидатов
подтвердил), плюс `users.new_per_day`. Отдельного кода не требует.

## 6. Правила по огласовкам

- Все арабские слова и предложения хранятся с огласовками.
- Приоритет — считать огласовки как есть с фото, а не расставлять заново.
- Vision-модель может терять часть харакат, поэтому шаг подтверждения/правки
  админом обязателен.
- Библиотека простановки огласовок — только запасной вариант для источников без
  огласовок. Вызывается через `services/tashkeel.py`, по умолчанию не
  используется.
- Неправильная харака = неправильно выученное произношение; качество здесь
  важнее скорости.

## 7. API для Mini App

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/stats` | счётчики для главной |
| GET | `/api/v1/queue/due` | карточки по расписанию (`ar_ru` и `ru_ar` вперемешку) |
| GET | `/api/v1/queue/new` | слова без прогресса, с учётом суточного лимита |
| GET | `/api/v1/queue/training?topic=&recent=` | все выученные вне расписания, только чтение. `topic` — метка слова, `recent=N` — N последних добавленных по `created_at` |
| POST | `/api/v1/review` | `{word_id, direction, rating}` → обновление FSRS, возвращает новый `due` |
| POST | `/api/v1/words/{id}/learn` | завести карточки для слова (кнопка у нового слова) |

Ответ карточки включает примеры (`sentence.arabic`, `translation_ru`) и для
каждого слова примера — признак «новое для тебя», посчитанный на сервере.

### Авторизация

Mini App присылает подписанные `initData`. Бэкенд проверяет подпись:
`HMAC_SHA256(key=HMAC_SHA256("WebAppData", bot_token), msg=data_check_string)`,
плюс свежесть `auth_date`. Ни один эндпоинт не принимает `telegram_id` от
клиента — только из проверенной подписи. Отсутствующий пользователь создаётся в
`users` при первом валидном запросе.

## 9. Принятые решения и обоснования

### Модель ИИ: `claude-sonnet-5`

Стоимость страницы учебника (~6 000 входных токенов с картинкой в высоком
разрешении + ~2 000 выходных с огласовками):

| Модель | $/1M вход/выход | Разрешение | ~страница | Учебник ~150 стр. |
|---|---|---|---|---|
| Haiku 4.5 | 1 / 5 | 1568px | ~$0.013 | ~$2 |
| Sonnet 5 | 3 / 15 (акция 2 / 10 до 31.08.2026) | 2576px | ~$0.03 | ~$5 |
| Opus 5 | 5 / 25 | 2576px | ~$0.08 | ~$12 |

Разница между самым дешёвым и выбранным вариантом — около четырёх долларов за
всё время жизни проекта, поэтому решающий фактор не цена, а разрешение. Харака —
штрих в несколько пикселей; Haiku 4.5 сжимает картинку до 1568px по длинной
стороне, Sonnet 5 держит 2576px. Модель вынесена в `AI_MODEL`, переключение и
сравнение на одной странице — одна строка в `.env`.

### FSRS считается на сервере

- «Тренировка» обязана не менять состояние. На сервере это отсутствие вызова —
  сломать нечего. На клиенте пришлось бы принимать посчитанное состояние, и
  любой баг во фронтенде (или DevTools) ломал бы интервалы всей колоды.
- Одна реализация вместо двух: библиотека Python, иначе нужен порт на JS и
  синхронизация версий.
- Прогресс переживает переустановку Telegram, открывается с любого устройства.
- История в `review_log` для будущей подгонки параметров всё равно нужна на
  сервере.

Плата — HTTP-запрос на карточку (~20–30 за сессию). Лечится оптимистичным UI:
следующая карточка показывается сразу, запрос уходит в фоне.

### `arabic-diacritizer` — опциональная зависимость

Единственный живой вариант (BiLSTM+attention, 6.6% DER, март 2026): `mishkal` —
2021 год, `shakkala` тянет TensorFlow, `libtashkeel` на PyPI не публикуется. Но
колесо весит 47 МБ и требует `torch>=2.1` (ещё ~1–2 ГБ) ради ветки кода, которая
по §6 в норме не вызывается. Поэтому: реализация написана и работает, но ставится
как `pip install -e ".[tashkeel]"`, и сборка без torch не раздувается.

### Frontend: Vue 3 + Vite

Соответствует конвенциям, по которым владелец проекта пишет сам (Vue 3 SFC, CSS
Modules, rem) — значит поддерживаемо без него. SPA без Nuxt: внутри Telegram SSR
не нужен, отдаём статику.

## 10. Этапы

Каждый этап заканчивается проверкой и ожидает одобрения владельца перед
переходом к следующему.

| # | Этап | Проверка |
|---|---|---|
| 1 | Каркас: `pyproject`, конфиг, docker-compose с Postgres 16, async SQLAlchemy, Alembic, пустые модели | контейнер Postgres поднят, `alembic upgrade head` проходит, скрипт проверки соединения печатает версию БД |
| 2 | Модели, миграция, сидер, нормализация арабского | тесты нормализации и дедупликации зелёные, сидер заливает 20 слов |
| 3 | Скелет бота: `/start` печатает Telegram ID, определение роли, `/help` | бот отвечает в Telegram, ID вписан в `.env` |
| 4 | Импорт по фото: FSM, vision, дедупликация, кнопки, запись | реальное фото страницы → слова и предложения в БД |
| 5 | FastAPI: валидация `initData`, очереди, FSRS | тесты подписи, очереди отвечают, `POST /review` двигает `due` |
| 6 | Mini App: три режима, переворот карточки, примеры с подсветкой новых слов | открывается в Telegram через cloudflared, карточки работают |
| 7 | Генерация предложений + кандидаты в новые слова | пакет предложений в БД, кандидат подтверждается кнопкой |
| 8 | Полировка: счётчики, фильтр по темам, суточный лимит, обработка ошибок, README | сценарий «новичок с нуля» проходит от `/start` до повторения |

Тесты вперёд там, где это чистая логика: нормализация, дедупликация, валидация
`initData`, переходы FSRS. UI проверяется вручную в Telegram.

Локальный Postgres 14 не трогается — база поднимается в Docker (16).

## 11. Вне объёма

- Продакшн-деплой: решается позже (сейчас только локальный запуск — polling +
  туннель cloudflared для HTTPS Mini App).
- Сущность «Урок», отдельный режим «только старые слова», аудио, картинки к
  словам, статистика по группе, несколько колод, роли сложнее «админ/пользователь».
- Обучение собственных параметров FSRS: данные для этого копятся в `review_log`,
  но сама подгонка не делается.
