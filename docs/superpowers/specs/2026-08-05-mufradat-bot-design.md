## 1. Что строим

Приложение в Telegram для группы ~10 человек, которые вместе учат литературный арабский
по учебнику «العربية بين يديك». Колода общая на всех.

Приложение не закрытое, и это осознанно: бот публичный, кнопку приложения получает любой,
кто его найдёт, а содержимое колоды — слова из учебника, который может купить кто угодно.
Наполнять её может только владелец — вот это и охраняется, проверкой `ADMIN_TELEGRAM_ID`
в боте.

| Вход | Кому | Зачем |
|---|---|---|
| Telegram Mini App | всем | учёба по карточкам |
| Чат с ботом | админу | ввод слов с телефона |
| Админка Django | staff | ввод и правка с компьютера, загрузка картинок |

Бот: **@mufradat_cards_bot**, имя «مفردات».

## 2. Роли

Админ ровно один — владелец. Его Telegram ID лежит в `ADMIN_TELEGRAM_ID`; отдельной
модели нет, потому что список из одного элемента не нуждается в таблице. Проверка в
одном месте — `apps/bot/permissions.is_admin`.

Staff в админке — обычные пользователи Django с паролем. Это отдельный механизм: у
ученика нет пароля, у staff нет Telegram ID.

## 6. Модель данных

### Entry — слово (есть в коде)

В админке раздел называется «Слова» (`verbose_name` — «Слово»). Имя класса остаётся
`Entry` — идентификаторы в проекте английские.

| Поле | Тип | Примечание |
|---|---|---|
| `arabic` | text | с огласовками, как ввёл владелец |
| `translation_ru` | text | |
| `transliteration` | text, blank | различает пары вроде `katabta` / `katabti` |
| `image` | ImageField, null | загружается через админку |
| `created_at` | timestamptz | по нему берутся последние слова для промпта |

Ограничение: `unique(arabic, translation_ru)`. По **точному** арабскому — пара «к
мужчине / к женщине» различается только последней харакой, и сравнение по скелету
запрещало бы женскую форму.

**Деления на слова и фразы нет.** Поле `kind` было и убрано по решению владельца
(миграция `0003`): «مَا اسْمُكَ؟» — такая же карточка, как «بَيْت», учится так же и
показывается так же. Пока разделение ни на что не влияло — ни на прогон, ни на ввод, —
оно только заставляло помнить о себе в шести местах: модель, разбор строки, админка,
API, промпт, фильтр в приложении.

Признак «это фраза» из данных не потерян: фраза — это многословное арабское,
`" " in arabic`. Если однажды понадобится, вычисляется запросом, а не хранится.

### Больше в базе ничего нет

Ни учеников, ни прогресса, ни истории ответов: пока повторения по расписанию
отложены (§7), хранить нечего. `Entry` — единственная таблица проекта.

`Sentence` и `SentenceEntry` из ранних ревизий отменены: фраза — это обычная `Entry`,
отдельной сущности «пример употребления» в проекте не будет.

### Отложено без даты

Словоформы (`base`, `person`, `tense`, `pos`) — карточки вида «его
машина», «я пишу». Владелец хотел их видеть; решение отложено до рабочего цикла
повторений. Пройденные местоимения: `ana`, `huwa`, `hiya`, `anta`, `anti`, `nahnu`.

## 7. Повторения по расписанию — отложены

Решение владельца: сначала простое — колода целиком, в случайном порядке, без учёта
успеха.

Обоснование: FSRS выигрывает там, где карточек сотни и повторить всё за день
невозможно, поэтому алгоритм решает, что можно пропустить. При семидесяти карточках
пропускать нечего — полный прогон это 5–10 минут, и сложность оплачивалась бы
экономией, которой нет.

Библиотека была осмотрена и обёртка написана — код удалён до коммита, поэтому в
истории его нет. Проверенные факты, чтобы не осматривать заново:

```
fsrs 6.3.1
Card().to_dict() → {card_id, state, step, stability, difficulty, due, last_review}
Rating           → Again=1, Hard=2, Good=3, Easy=4
Scheduler().review_card(card, rating, review_datetime=None) → (Card, ReviewLog)
```

Главная граница между оценками — не там, где кажется: провалом считается только
`Again`, а `Hard` это успех, доставшийся с трудом (`recall = 0 if rating == Again
else 1` в оптимизаторе). На зрелой карточке с интервалом 11 дней: `Again` → 10 минут,
`Hard` → 32 дня, `Good` → 46, `Easy` → 77.

Когда повторения вернутся, считать их надо **на сервере**: библиотека на Python,
иначе нужен порт на JS и синхронизация двух реализаций; прогресс переживает
переустановку Telegram.

## 8. Наполнение базы

### Ввод через бота (работает)

Строка `арабское | перевод` или `арабское | перевод | транслитерация`.

**Порядок частей не важен.** Каждая часть определяется по алфавиту: арабский,
кириллица и латиница лежат в непересекающихся диапазонах Unicode. Поэтому
`بَيْت | дом`, `дом | بَيْت` и `bayt | дом | بَيْت` разбираются одинаково.

Дубли не падают ошибкой — бот отвечает «Уже есть». Нераспознанная строка возвращает
причину и формат. Не-админ получает отказ с кнопкой приложения.

**Карточек в сообщении сколько угодно, каждая на своей строке.** ИИ отдаёт список из
пятнадцати строк, и вводить их по одной было главной ручной работой в проекте.

| Решение | Почему так |
|---|---|
| Плохая строка не отменяет остальные | список приходит целиком; из-за одной опечатки переписывать его незачем — вернуть надо именно её |
| Непонятая строка возвращается целиком, без номера | сама строка опознаётся точнее, чем «строка 7», и её можно скопировать, поправить и отправить снова |
| Добавленные карточки перечисляются в ответе | огласовки проверяются только глазами: в ответе видно, что именно легло в базу и не уехала ли транслитерация в перевод |
| Отчёт делится на «Добавлено», «Уже есть», «Не разобрал» со счётчиками | после вставки пятнадцати строк нужно одно число, а не пятнадцать сообщений |
| Списки в отчёте подрезаются до 30 с «и ещё N» | сообщение Telegram — 4096 знаков; молча терять хвост нельзя |
| Текст карточки экранируется | ответ уходит разметкой HTML, а `<` из перевода ломал бы сообщение целиком |

### Ввод через админку (работает)

То же самое с компьютера, плюс загрузка картинок.

### Кнопка «Промпт для ИИ» (работает)

**ИИ к приложению не подключается.** Ни ключа, ни модели, ни `curriculum.yaml`, ни
генерации на сервере. Вместо этого бот отдаёт админу готовый текст, тот сам идёт к
любому ИИ, получает слова и фразы и вводит их руками — одним сообщением, всеми строками
сразу.

Кнопка живёт на reply-клавиатуре админа, потому что нужна несколько раз в неделю.
Нажатие приходит обычным текстом, поэтому `prompt.router` подключён **раньше**
`add.router`: иначе название кнопки уехало бы в разбор карточки.

В сообщении: инструкция и последние 100 карточек одним списком. Отдельного блока фраз
больше нет — он держался на `kind` (§6); фразы всё равно попадают в список наравне со
словами, и манеру модель по ним видит. Тему ИИ предлагает сам, глядя на список; поэтому
вести темы на нашей стороне не нужно. Запрошенный формат ответа совпадает с форматом
ввода бота, и теперь ответ можно скопировать целиком, всеми строками сразу.

Лимит Telegram — 4096 знаков, и сотня записей с уточнениями в него не влезет. Список
набирается от новых к старым, пока помещается, и в блоке сказано, сколько слов вошло:
«последние сто» — это окно, и молча превращать его в «последние сколько-то» нельзя.

Распознавания страниц учебника **нет**: владелец вводит слова сам, и это снимает
главный риск проекта — потерянные при распознавании огласовки.

## 9. Учёба в Mini App

Трёх режимов («на сегодня», «новые», «тренировка») больше нет — они существовали ради
расписания. Вместо них один прогон: вся колода в случайном порядке, и пока карточки не
кончились, прогон не пройден.

**Карточка. Направление случайное у каждой.** Одна приходит арабским вперёд — на обороте
перевод; другая русским — на обороте арабское. Монетка бросается на каждую карточку в
момент, когда прогон собирается, и запоминается вместе с порядком: внутри прогона
карточка не меняет сторону, а новый прогон раздаёт направления заново. Так одна колода
тренирует и узнавание, и производство, а разнобой не даёт привыкнуть к одной стороне.

Оба направления в одном прогоне, а не переключателем: переключатель — это выбор, который
ученик делает в пользу лёгкого, а трудное как раз полезнее (§12). Каждое слово за прогон
встречается один раз, в одну сторону; обе стороны набегают за несколько прогонов. Если
понадобится гарантированное покрытие обеих сторон, карточка входит в прогон дважды и
прогон становится вдвое длиннее — это отдельное решение, сейчас его нет.

**Картинка всегда на обороте, в любом направлении.** На лице она выдавала бы ответ:
вместо припоминания получилось бы узнавание картинки. Оборот — это ответ, поэтому там же
живёт и транслитерация. Переворачивать можно сколько угодно, время не ограничено.

**Ход.** Кнопки «Назад» и «Далее» плюс счётчик «12 / 70». Прогон — это список с
индексом, поэтому «далее» и «назад» — это ±1, и к прошедшей карточке всегда можно
вернуться. Кнопок «помню» и «не помню» нет: без расписания оценке некуда записываться,
а прогон закрывается тем, что список кончился.

**«Завершить».** Прогон можно бросить на середине: состояние стирается, приложение
возвращается на начальный экран. Это выход из снимка — добавили слова и хотите их
сейчас, а не в следующий заход: завершили прогон, начали новый, и он приходит с
новым запросом, уже со свежими словами.

| Решение | Как | Почему так |
|---|---|---|
| Прогон — снимок | колода получена одним запросом при открытии | снимок получается сам собой; дополнять живой прогон значит опрашивать сервер и сливать списки, а «Завершить» и без этого пускает новые слова сразу |
| Состояние в `localStorage` | список id и индекс пишутся после каждого шага | свернул окно посреди прогона — продолжил с того же места, иначе «прогон не закрыт» ничего не значит. `CloudStorage` Telegram дал бы синхронизацию между устройствами, но требует асинхронной обвязки, а прогон живёт 5–10 минут на одном телефоне |
| Порядок — в приложении | сервер отдаёт колоду как есть | «перемешать заново» работает без запроса |

Прогон один за раз: начал новый — предыдущий забыт. Слова, добавленные посреди прогона,
попадают в следующий: он начинается с нового запроса.

### Как это сделано (готово)

Экранов два. Начальный: заголовок «مفردات», строка «В колоде 50 слов» и кнопка «Начать
тренировку». Прогон: «Завершить» сверху, карточка во всю высоту, снизу «Назад», счётчик,
«Далее».

| Решение | Как | Почему так |
|---|---|---|
| Начальный экран — одна кнопка | фильтров «Слова / Фразы / Всё» нет: колода одна и плоская (§6) | выбирать было не из чего, кроме размера прогона, а он и так весь |
| Размер колоды виден до начала | «В колоде 50 слов», формы числа считает `utils/plural.ts` | видно, что колода растёт, и сколько всего предстоит. «50 слов», но «21 слово» и «11 слов» — руками такое не подставить |
| Конец колоды закрывает прогон | на последней карточке «Далее» называется «Готово» и делает то же, что «Завершить» | список кончился — закрывать его больше нечем, а отдельная кнопка «прогон пройден» показывала бы то же самое второй раз |
| Сторона карточки живёт в контроллере | `RunController` держит `isFlipped` и сбрасывает его, когда меняется `card.entry.id` | только он знает, что карточка сменилась. Держи флаг сама карточка — новая приходила бы оборотом вверх, и ответ был бы виден до припоминания |
| Направление лежит в прогоне | `localStorage` хранит `[{ id, isReversed }]`, а не список номеров | монетка брошена один раз при сборке прогона. Считай направление на ходу — перезагрузка и шаг назад показывали бы карточку другой стороной |
| Лицо и оборот меняются местами | `front` и `back` — вычисляемые стороны, каждая знает, арабская она или русская | правило одно на оба направления: на лице вопрос, на обороте ответ с транслитерацией и картинкой. Иначе разметка удвоилась бы |
| Оба лица всегда в разметке | переворот — `rotateY` на обёртке, лица наложены друг на друга | высоту задаёт контейнер, поэтому карточка не прыгает от длины ответа |
| Перелистывание со сдвигом | `Transition` с классами `slide-forward` / `slide-back`, карточки накладываются на сцене | видно, что карточка сменилась и в какую сторону. Направление ставится до эмита, поэтому новая карточка приезжает уже с нужной стороны |
| API зовётся своим же адресом | относительный `/api/v1/entries/`, прокси Vite на Django | нет ни CORS в разработке, ни разъезда `http`/`https` при работе через туннель. `VITE_API_URL` пригодится, только если фронтенд и бэкенд разъедутся по доменам |
| Прокси не подменяет `Host` | `{ target, changeOrigin: false }`, а не короткая запись `'/api': target` | адрес картинки Django собирает из `Host`. С `changeOrigin: true` (короткая запись включает его сама) телефон получал `http://127.0.0.1:8000/m/…` — то есть ссылку на самого себя, и картинка не грузилась |

**Внутри Telegram или нет — определяется по `platform`, а не по наличию объекта.**
`telegram-web-app.js` создаёт `window.Telegram.WebApp` на любой странице и отдаёт
`colorScheme: 'light'`. Проверка «объект есть» ставила приложению светлую тему в обычном
браузере вопреки системной; вне клиента `platform === 'unknown'`. Цвета клиента
(`themeParams`) ложатся в наши CSS-переменные, `colorScheme` — в `data-theme` на
`<html>`; вне Telegram тему задаёт `prefers-color-scheme`.

Шрифт арабского — системный насх (`SF Arabic`, `Noto Naskh Arabic`): своего не везём,
огласовки читаются. Если на каком-то устройстве харакаты поедут, лечится файлом шрифта в
`frontend/src/assets/`.

## 10. API для Mini App (работает)

Один эндпоинт: `GET /api/v1/entries/` — вся колода одним списком, `id`, `arabic`,
`translation_ru`, `transliteration`, `image` (полный URL: приложение живёт на другом
домене). Семьдесят записей — это один небольшой ответ, поэтому тасовать и перекладывать
сторону карточки дешевле в приложении: «перемешать заново» тогда работает без запроса.
Постраничности нет намеренно — она разрезала бы снимок прогона.

`ListAPIView` с `ModelSerializer`: это ровно список модели, и писать `APIView` руками
здесь нечего.

**Аутентификации нет.** Проверка подписи `initData` была написана и удалена по решению
владельца. Разбор, почему она ничего не давала:

- охранять нечего — это слова из учебника, без личных данных, без записи и без прогресса;
- «закрытым» она приложение не делала: бот публичный, любой пользователь Telegram может
  открыть приложение, и его `initData` будет подписан правильно. Проверка доказывала
  «пришёл настоящий пользователь Telegram через наше приложение», а не «это один из
  наших десяти»;
- картинки всё равно открыты: `image` — обычный файл по прямому URL.

Подпись вернётся вместе с прогрессом у каждого своего — и не ради секретности, а ради
личности: без неё клиент мог бы прислать любой `telegram_id` и залезть в чужой прогресс.
См. §12.

## 11. Конфигурация

`.env` в корне, читается через `load_dotenv` в `settings.py`. Уже заданные переменные
окружения не перезаписываются, поэтому в Docker побеждает реальное окружение.
`.env.example` содержит только имена.

```
POSTGRES_USER  POSTGRES_PASSWORD  POSTGRES_NAME  POSTGRES_HOST  POSTGRES_PORT
DJANGO_SECRET_KEY  DJANGO_DEBUG
BOT_TOKEN  ADMIN_TELEGRAM_ID  WEBAPP_URL
```

У приложения свой `frontend/.env.example` с одной переменной `VITE_API_URL`, и она
пустая: адрес API совпадает с адресом приложения.

Те же `POSTGRES_*` читает `docker-compose.yml`, поэтому данные БД нигде не
дублируются. Внутри контейнера имя базы приходит как `POSTGRES_DB` — это имя образа,
а `POSTGRES_NAME` наше, снаружи.

**Токен бота стоит перевыпустить** через `/revoke` у @BotFather: при отладке он попал
в вывод терминала.

## 12. Отложено, но не отменено

Открытых вопросов нет. Отложенное — с условием, при котором к нему возвращаются.

## 13. Принятые решения и обоснования

### Django вместо FastAPI

Владелец поддерживает Django сам. Менять пришлось весь слой данных, иначе в проекте
оказались бы две ORM. Побочный выигрыш: админка закрывает ввод и правку без кода.

Цена: процесс бота асинхронный, а `transaction.atomic()` синхронный. Пока не мешает —
записи одиночные; при пакетных операциях функция пишется синхронной и вызывается
через `asgiref.sync.sync_to_async`.

### Одна таблица `Entry` на слова и фразы

Слово и фраза структурно совпадают, поэтому сначала их различало поле `kind`, а потом и
оно ушло (§6). Отдельные таблицы вынудили бы всё, что читает колоду, склеивать два
запроса — а колоду читают и приложение, и промпт для ИИ.

### Нормализация арабского удалена

`normalize_arabic` приводил слово к скелету без огласовок и ловил дубли, пришедшие с
разной расстановкой харакат. Смысл был при распознавании с фото. Ввод ручной, поэтому
от повторов достаточно ограничения в БД на точную пару. Код восстанавливается из
коммита `171860f`.

### Полей меньше, чем в ранних ревизиях

`source` убран — у всех записей было бы одно значение: их вводит владелец. `topic`
убран — деления на темы у группы нет, колода плоская, а тему для новых слов предлагает
ИИ, глядя на промпт. Схема заводится тем этапом, который ей пользуется, чтобы не
замораживать в миграции непроверенное.

### Тестов на `settings` нет

Конфигурация проверяется тем, что проект поднимается. Тесты идут туда, где логика:
разбор строки ввода, права, модель, сборка промпта.

### Асинхронные тесты требуют `django_db(transaction=True)`

Асинхронные запросы ORM идут по своему соединению и не попадают в транзакцию, которую
откатывает обычный `django_db`. Без маркера записи текут между тестами, и проверки
вида «ничего не сохранилось» ложно проходят.

Остаётся предупреждение в конце прогона: тестовая база не удаляется, потому что
асинхронное соединение остаётся открытым. Попытка закрывать его автоиспользуемой
фикстурой ломает синхронные тесты. Косметика.

## 14. Вне объёма

- Развёртывание: контейнеры `web` и `bot`, VPS, статика — отдельным заходом.
- ИИ внутри приложения: ни ключа, ни вызовов на сервере. Бот отдаёт промпт, дальше
  владелец идёт к ИИ сам — §8.
- Распознавание страниц учебника, автоподбор картинок, библиотека простановки
  огласовок — отменены.
- Озвучка, корень и порода глагола — исключены владельцем.
- Статистика по группе, напоминания «пора повторять» — не запрашивались.
- Сущность «Урок», деление на темы, несколько колод, больше одной картинки.
- Режим-тренажёр спряжений: владелец просил формы видеть, а не отрабатывать.
