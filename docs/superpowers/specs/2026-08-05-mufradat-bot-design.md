# Mufradat Bot — дизайн

Дата: 2026-08-05

**Ревизия 4.** Против ревизии 3: распознавание страниц учебника убрано — слова
вводятся вручную, через бота с телефона и через админку с компьютера. Вместе с ним
ушли автоподбор картинок из Openverse и библиотека простановки огласовок. За ИИ
осталось две задачи: составлять предложения-примеры из пройденной лексики и предлагать
по одному-два новых слова в неделю.

## 1. Что строим

Закрытое приложение внутри Telegram для группы ~10 человек, которые вместе учат
литературный арабский по учебнику «العربية بين يديك». Колода общая на всех: админ
наполняет базу, остальные учат по карточкам. Прогресс у каждого свой.

Три входа:

| Вход | Кому | Зачем |
|---|---|---|
| Telegram Mini App | всем | учёба по карточкам |
| Чат с ботом | админу | ввод слов с телефона, генерация |
| Админка Django | staff | ввод и правка с компьютера, загрузка картинок |

## 2. Роли

| Роль | Права |
|---|---|
| Админ (Telegram ID из `ADMIN_TELEGRAM_IDS`) | Ввод слов через бота и генерация. Плюс всё, что может пользователь. |
| Пользователь | Только учёба через Mini App и свой прогресс. Никаких вызовов ИИ. |
| Staff в админке Django | Правка базы через веб-админку, вход по логину и паролю Django. |

Гейтинг телеграм-админа — по Telegram ID из конфигурации, проверка в одном месте
(фильтр aiogram). Это отдельный от Django-аккаунтов механизм: у ученика нет
пароля, у staff нет Telegram ID, смешивать их в кастомной модели пользователя
незачем.

### Бот и Django ORM

Процесс бота вызывает `django.setup()` и работает с ORM напрямую. Два места, где
это требует внимания:

- Чтение и одиночные записи — через асинхронные методы ORM (`aget`, `acreate`,
  `async for`).
- **`transaction.atomic()` асинхронного варианта не имеет.** Сохранение
  подтверждённого набора — одна транзакция на много строк, поэтому эта функция
  пишется синхронной и вызывается через `asgiref.sync.sync_to_async`.

## 4. Модель данных

Сущность «Урок» не создаётся, и деления на темы тоже нет: колода общая и плоская.
Ограничение ИИ-генерации пройденной лексикой закрывается тем, что вся таблица
`Entry` и есть пройденная лексика, а порядок ввода нового — полем `created_at`
плюс суточный лимит.

### Схема строится по частям

Полная схема ниже — целевая. Таблицы заводятся тем этапом, который ими реально
пользуется, чтобы не замораживать в миграции то, что ещё не проверено кодом:

| Что | Появляется на этапе |
|---|---|
| `Entry`: слово, фраза, картинка | 2 — домен |
| `TelegramUser`, `UserProgress`, `ReviewLog` | 5 — вместе с FSRS |
| `Sentence`, `SentenceEntry` | 7 — там их создаёт генерация |
| Формы: `kind=form`, `base`, `person`, `tense`, `pos` и их ограничения | позже, отдельным решением |

### Entry — единица заучивания

Одна таблица на всё, что попадает в карточки. Слово, фраза и словоформа
структурно не различаются: арабское с огласовками, перевод, транслитерация,
картинка, примеры. Различаются только типом.

| kind | Пример | Что это |
|---|---|---|
| `word` | `بَيْت` — дом | слово |
| `phrase` | `مَا اسْمُكَ؟` — как тебя зовут? (к мужчине) | функциональная фраза |
| `form` | `سَيَّارَتُهُ` — его машина | словоформа с местоимением |

Поля:

| Поле | Тип | Примечание |
|---|---|---|
| `id` | PK | |
| `kind` | choices | `word` \| `phrase` \| `form` |
| `arabic` | text | с огласовками, как ввёл владелец |
| `translation_ru` | text | у формы — «его машина», у фразы — с пометкой «(к мужчине)» |
| `transliteration` | text, null | |
| `pos` | choices, null | `noun` \| `verb`; нужен, чтобы знать, какие формы уместны |
| `base` | FK на Entry, null | заполнен у `form`: у `سَيَّارَتُهُ` это `سَيَّارَة` |
| `person` | choices, null | `ana`, `huwa`, `hiya`, `anta`, `anti`, `nahnu`. У `form` — лицо формы; у `phrase` — к кому обращение (`anta` / `anti`) |
| `tense` | choices, null | у глагольных форм: `past` \| `present`; у притяжательных пусто |
| `source` | choices | `textbook` \| `manual` \| `ai_generated` |
| `image` | ImageField, null | загружается через админку |
| `created_at` | timestamptz | |

Ограничения:

- `unique_together = ("arabic", "translation_ru")` — по **точному** арабскому, а не
  по нормализованному. Причина в §4.1: пары «к мужчине / к женщине» различаются
  только харакой, и уникальность по скелету запрещала бы половину нужного контента.
- У формы `base` и `person` обязательны, `unique_together = ("base", "person",
  "tense")`. `person` и `tense` хранят пустую строку, а не NULL, — иначе две
  притяжательные формы с пустым `tense` прошли бы обе, так как в Postgres NULL-ы
  считаются различными.
- Картинка формы наследуется от базы на уровне представления (`image or
  base.image`), в БД не копируется.
- `arabic_norm` заполняется в `save()` модели, а не вызывающим кодом, чтобы
  инвариант нельзя было забыть. `bulk_create` обходит `save()` — там норму нужно
  проставлять явно.

### Остальные модели

| Модель | Поля |
|---|---|
| `TelegramUser` | `telegram_id` (PK, BigInteger), `username`, `first_name`, `new_per_day` (int, 5), `created_at` |
| `Sentence` | `id`, `arabic`, `translation_ru`, `source`, `created_at` — только примеры употребления, карточками не становятся |
| `SentenceEntry` | `sentence` (FK), `entry` (FK), `unique_together` |
| `UserProgress` | `id`, `telegram_user` (FK), `entry` (FK), `direction`, `due`, `fsrs_state` (JSONField), `updated_at`; `unique_together = (telegram_user, entry, direction)`, индекс `(telegram_user, due)` |
| `ReviewLog` | `id`, `telegram_id` (BigInteger, **без FK** — история переживает удаление пользователя), `entry` (FK), `direction`, `rating` (1..4), `reviewed_at` |

`UserProgress` ссылается на `Entry` одним FK — поэтому очереди, три режима и два
направления не усложняются от того, что единицы бывают трёх типов.

Модель учеников называется `TelegramUser`, а не `User`: имя `User` и таблица
`auth_user` заняты Django.

Все временные метки — `TIMESTAMPTZ` (`USE_TZ = True`). `kind`, `pos`, `person`,
`tense`, `direction`, `source` — `TextChoices`, в БД хранятся значения.

## 5. Наполнение базы

Два источника. Распознавания страниц учебника нет: владелец вводит слова сам, и это
снимает главный риск проекта — потерянные при распознавании огласовки.

### 5.1. Ручной ввод

Основной путь. Через бота — строкой `арабское | перевод`, чтобы заводить слова с
телефона сразу после занятия. Через админку Django — когда есть компьютер: там же
удобнее править и прикладывать картинки.

Огласовки ставит владелец, поэтому подтверждать нечего: что набрано, то и в базе.
От повторов защищает ограничение в БД: пара «арабское + перевод» уникальна.

### 5.2. ИИ-генерация

Единственное, что делает ИИ, и только по команде админа:

- **предложения-примеры** из уже пройденной лексики плюс служебный набор;
- **новые слова**, по одному-два в неделю, отдельным списком на подтверждение.

Правила берутся из `content/curriculum.yaml` (§6): темы, примеры, список лиц,
максимум одно новое слово на предложение. Результат кэшируется в базе.

## 6. Файл поведения ИИ (`content/curriculum.yaml`)

Редактируется без правки кода. Формат — YAML (нужны комментарии), читается через
Pydantic, поэтому опечатка даёт внятную ошибку, а не странный промпт.

Главный рычаг — **примеры**, а не инструкции прозой: модель на порядок точнее
ловит стиль по двум-трём образцам, чем по описанию. Дописал пример в тему —
изменилась вся её выдача.

```yaml
rules:
  register: msa                      # литературный, по «العربية بين يديك»
  harakat: required
  max_new_words_per_sentence: 1
  forms_per_entry: 2                 # сколько форм просить на слово
  pronouns: [ana, huwa, hiya, anta, anti, nahnu]
  service_words: [فِي, مِنْ, إِلَى, هَذَا, هَذِهِ]

topics:
  - id: introductions
    title: Знакомство
    enabled: true
    target_count: 12
    ask_for:
      - вопрос и ответ об имени
      - вопрос и ответ о происхождении
    examples:
      - ar: مَا اسْمُكَ؟
        ru: как тебя зовут? (к мужчине)
      - ar: مِنْ أَيْنَ أَنْتَ؟
        ru: откуда ты? (к мужчине)
```

`pronouns` — центральная настройка: один список управляет и тем, какие лица
генерировать в формах, и тем, какие использовать во фразах. Прошли новое
местоимение — дописал строку. Отдельной настройки «формы обращения» нет: `anta` и
`anti` в этом списке и есть «(к мужчине)» и «(к женщине)».

Темы включаются и выключаются флагом `enabled`, не удаляясь.

## 7. Учёба в Mini App

Карточка: единица на лицевой стороне, тап → переворот. Каждая единица даёт две
независимые карточки: `ar_ru` и `ru_ar`.

Что на какой стороне — вопрос корректности, а не оформления:

| Направление | Лицо | Оборот |
|---|---|---|
| `ar_ru` | арабское с огласовками | перевод, транслитерация, **картинка**, примеры |
| `ru_ar` | перевод + **картинка** | арабское с огласовками, транслитерация, примеры |

Картинка на лице `ar_ru` выдала бы ответ — вместо припоминания перевода получилось
бы узнавание картинки. На `ru_ar` она арабского не выдаёт, а припоминание идёт от
образа, а не от русского слова, что сильнее. Полный список форм на обороте **не
показывается** — форма является отдельной карточкой.

Три режима:

| Режим | Что даёт | Пишет в FSRS |
|---|---|---|
| «На сегодня» | что пора по расписанию, старое и новое вперемешку | да |
| «Новые» | единицы без прогресса, с учётом `new_per_day`; на кнопке счётчик | да (создаёт карточку) |
| «Тренировка» | всё выученное вне расписания, при желании «последние N добавленных» | **нет** |

Отдельного режима «только старые» нет — его закрывает фильтр в «Тренировке».

«Новизна» слова в примере **не хранится**: слово считается новым, если для него нет
строки в `UserProgress`. Считается на сервере, у каждого своё. Такое слово
подсвечивается в примере, рядом кнопка «Добавить в изучение».

### Картинки

Загружаются вручную через админку. Автоподбор из открытых банков рассматривался и
отклонён: он тянет внешний API, разбор лицензий и риск нерелевантной картинки, а
пользы даёт мало — картинки нужны конкретным существительным и бесполезны для
абстракций и частиц, то есть их и так немного.

Хранится файл в `media/`, поле `image` у `Entry`.

## 8. Правила по огласовкам

- Всё арабское хранится с огласовками.
- Огласовки ставит владелец при вводе, поэтому подтверждать нечего.
- **У словоформ и парных фраз транслитерация обязательна.** `كَتَبْتَ` (ты написал) и `كَتَبْتِ`
  (ты написала) различаются только последней харакой — ровно то различие, которое
  группа сейчас учит. Глазами разницу в одной точке легко пропустить, а `katabta` /
  `katabti` не спутаешь, поэтому при подтверждении сгенерированного транслитерация показывается рядом.
- Неправильная харака = неправильно выученное произношение; качество здесь важнее
  скорости.

## 9. API для Mini App (DRF)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/stats/` | счётчики для главной |
| GET | `/api/v1/queue/due/` | карточки по расписанию |
| GET | `/api/v1/queue/new/` | единицы без прогресса, с учётом суточного лимита |
| GET | `/api/v1/queue/training/?recent=` | всё выученное вне расписания, только чтение. `recent=N` — N последних добавленных |
| POST | `/api/v1/review/` | `{entry_id, direction, rating}` → обновление FSRS, возвращает новый `due` |
| POST | `/api/v1/entries/<id>/learn/` | завести карточки для единицы |

Реализация — классы `APIView` с сериализаторами DRF. `ModelViewSet` не
используется: это не CRUD над моделью, а вычисляемые очереди.

### Авторизация

Mini App присылает подписанные `initData`. Проверка — в собственном классе
DRF-аутентификации: `HMAC_SHA256(key=HMAC_SHA256("WebAppData", bot_token),
msg=data_check_string)` плюс свежесть `auth_date`; при успехе возвращается
`TelegramUser`. Ни один эндпоинт не принимает `telegram_id` от клиента — только из
проверенной подписи. Отсутствующий пользователь создаётся при первом валидном
запросе.

## 10. Конфигурация (`.env`)

Параметры БД задаются по частям: их читают и `docker-compose.yml`, и Django, нигде
не дублируясь. `.env.example` содержит только имена и комментарии; значения живут в

## 11. Принятые решения и обоснования

### Django вместо FastAPI

Владелец поддерживает Django сам. Менять пришлось не «слой API», а весь слой
данных, иначе в проекте оказались бы две ORM: ушли SQLAlchemy, Alembic и asyncpg,
пришли Django ORM, миграции Django и psycopg 3.

Побочный выигрыш: **админка Django закрывает требование «править базу» без единой
строки кода** — из объёма уходит отдельный редактор через бота. Плюс
`pytest-django` сам создаёт и удаляет тестовую базу, поэтому отдельная база и
init-скрипт для неё не нужны.

Цена: процесс бота асинхронный, а `transaction.atomic()` синхронный (см. §3).

### Одна таблица `Entry` вместо трёх

Слово, фраза и словоформа структурно совпадают. Альтернатива — отдельные таблицы и
`UserProgress` с несколькими nullable FK и constraint «заполнен ровно один»;
сложность переехала бы в слой очередей, самый нагруженный код проекта (три режима ×
два направления × вычисление новизны).

### Модель ИИ: `claude-sonnet-5`

Стоимость страницы учебника (~6 000 входных токенов с картинкой в высоком
разрешении + ~2 000 выходных с огласовками):

| Модель | $/1M вход/выход | Разрешение | ~страница | Учебник ~150 стр. |
|---|---|---|---|---|
| Haiku 4.5 | 1 / 5 | 1568px | ~$0.013 | ~$2 |
| Sonnet 5 | 3 / 15 (акция 2 / 10 до 31.08.2026) | 2576px | ~$0.03 | ~$5 |
| Opus 5 | 5 / 25 | 2576px | ~$0.08 | ~$12 |

Разница между самым дешёвым и выбранным — около четырёх долларов за всё время
жизни проекта, поэтому решающий фактор не цена, а разрешение: харака — штрих в
несколько пикселей, Haiku сжимает картинку до 1568px, Sonnet 5 держит 2576px.
Модель вынесена в `AI_MODEL`.

### FSRS считается на сервере

- «Тренировка» обязана не менять состояние. На сервере это отсутствие вызова —
  сломать нечего. На клиенте пришлось бы принимать посчитанное состояние, и любой
  баг во фронтенде ломал бы интервалы всей колоды.
- Одна реализация вместо двух: библиотека Python, иначе нужен порт на JS.
- Прогресс переживает переустановку Telegram, открывается с любого устройства.
- История в `ReviewLog` для будущей подгонки параметров всё равно нужна на сервере.

Плата — HTTP-запрос на карточку (~20–30 за сессию). Лечится оптимистичным UI:
следующая карточка показывается сразу, запрос уходит в фоне.

### Библиотека огласовок не нужна

Она была запасным вариантом для источников без харакат — то есть для распознавания
страниц. Ввод ручной, генерация обязана возвращать огласованный текст, поэтому
ветки, которая бы её вызвала, не осталось. Заодно из проекта уходит `torch` весом
1–2 ГБ.

### Frontend: Vue 3 + Vite

Соответствует конвенциям, по которым владелец пишет сам (Vue 3 SFC, CSS Modules,
rem). SPA без Nuxt: внутри Telegram SSR не нужен, отдаём статику.

## 12. Этапы

Каждый этап заканчивается проверкой и ожидает одобрения владельца.

| # | Этап | Проверка |
|---|---|---|
| 1 | Каркас: Django-проект, конфиг, Postgres 16 в Docker | `manage.py check` и `migrate` проходят |
| 2 | Домен: модель `Entry`, картинка, админка, `curriculum.yaml`, сидер | тесты зелёные, админка открывается, слово заводится руками |
| 3 | Скелет бота: `/start` печатает Telegram ID, роли, кнопка Mini App | бот отвечает, ID вписан в `.env` |
| 4 | Ввод через бота: `арабское \| перевод` с телефона | слово с занятия попало в базу с телефона |
| 5 | DRF + FSRS: аутентификация по `initData`, очереди, повторения | очереди отвечают, `POST /review/` двигает `due` |
| 6 | Mini App: три режима, переворот карточки, картинка | открывается в Telegram через cloudflared |
| 7 | Генерация: предложения-примеры и новые слова по темам (здесь появляется `Sentence`) | пакет предложений в БД, кандидат подтверждается кнопкой |
| 8 | Полировка: счётчики, фильтры, лимиты, обработка ошибок | сценарий «новичок с нуля» проходит от `/start` до повторения |

Тесты вперёд там, где чистая логика: нормализация, сопоставление слов, поиск
похожих, загрузчик конфига, валидация `initData`, переходы FSRS. UI проверяется
вручную в Telegram.

Локальный Postgres 14 не трогается — база в Docker (16) на порту 5433.

## 13. Вне объёма

- Продакшн-деплой: позже (сейчас локальный запуск — polling + туннель cloudflared
  для HTTPS Mini App).
- Озвучка слов; корень и порода глагола — исключены владельцем.
- Статистика по группе, напоминания «пора повторять» — не запрашивались.
- Сущность «Урок» и деление на темы, режим «только старые слова», несколько колод,
  больше одной картинки на единицу.
- Режим-тренажёр спряжений («поставь глагол в форму для „она"») — владелец просил
  видеть формы, а не отрабатывать их отдельным упражнением.
- Подгонка параметров FSRS под группу: данные копятся в `ReviewLog`, сама подгонка
  не делается.
